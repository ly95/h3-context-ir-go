# 实现与验收状态

更新日期：2026-10-20。当前为实验实现，尚不能宣称完整复现 MiniMax H3-Context-IR，也不能直接宣称生产就绪。

`v0.1.0` 是最初发布的基础版本。审计修复和真实 DeepSeek 适配位于后续提交；不会改写已发布标签来隐藏初版的缺陷。

## 已实现的范围

| 部分 | 当前证据 | 仍不证明什么 |
| --- | --- | --- |
| Go 核心 IR、严格 JSON、Schema、跨引用与时间线校验 | 本地单元、集成、race、vet；Schema 同步测试 | 自由文本语义正确 |
| H3 五种模式、引用、对白、歌唱、复用音轨 cue | 公开指南的规则测试；固定官方 ComfyUI 源码提取的 socket/帧数/尺寸合同 | 已连接实际推理服务 |
| Planner 的原始输入保护 | 模式、目标、素材、固定对白、约束和显式 Bindings 校验；默认完整感知覆盖 | 模型没有遗漏任意自由文本要求 |
| DeepSeek Responses 客户端 | 本地 HTTP 协议测试；真实调用结果保存在 evals | 任意模型或接口都兼容 |
| DeepSeek 图片观察 | 传入实际图片与独立 Evidence Schema；合成红色圆形的真实观察记录 | 视频动作、音轨或复杂视觉理解已经验收 |
| 保存与重放 | 成功案例需重新编译后 artifact hash 相同 | 实际视频可按同样随机过程重现 |

感知范围是适配器的声明。完整覆盖意味着承诺检查相应轨道，不能被解读成语义准确率保证。视频仅抽帧、音频仅转写均不能冒充完整多模态理解。

## 已发现并修复的实质问题

- 基础首尾帧的 manifest 原先错误使用全参考 socket；现使用官方原生节点的 `first_frame` / `last_frame`。
- 音频作用镜头曾在渲染和 manifest 中丢失；现保留 target uses、源区间与锚点。
- 复用音轨的歌词 cue 原先不能表达；现与独立生成歌唱、说话人分开。
- 单个完整最终音轨与其它音轨 copy 的冲突、voice reference 错当 signal copy 现在明确拒绝。
- 请求原先缺少首尾帧等职责锁定；现由非空 `Request.Bindings` 提供完整允许集合。
- 感知原先只有文字 limitations；现显式记录完整/部分覆盖，默认拒绝未声明覆盖。
- 默认阻止调用者固定对白之外的新对白；新增台词必须显式允许。
- 模型适配器原先不存在；现在真实接口与图片观察有独立实现和用量记录。

真实 DeepSeek 三轮记录已保存：首轮 0/3；第二轮在一次修复后 2/3；第三轮 Planner v4 配合显式 `low` 思考模式，3/3 首次规划通过。第三轮共发生三次规划和一次真实图片观察，完成 IR 校验、H3 编译与持久化重放。全部历史失败和用量保留，详见 [评测说明与原始合成结果](../evals/README.md)。这三个合成案例不足以建立可靠率结论，也不能单独归因哪项调整带来了改善。

## 尚未完成

1. 任意自由文本的完整意图抽取、Claims 的完备性与语义蕴含验证。现有结构校验无法证明每句话都来自请求或观察；省略 Claims 的错误场景仍可能通过。
2. 内置视频与音频感知。DeepSeek 当前适配器明确只接受静态图片。源媒体读取、解码、裁剪、同步和探测由调用方的显式适配器执行。
3. 真实 H3 推理及成片对照评测，包括人物一致性、动作、音画同步、多镜头对白、属性迁移和参考强度。
4. ComfyUI `MiniMaxH3AddGuide`、可见文字中嵌套 ASCII 引号的无歧义编码、独立画外歌唱等边界。
5. 多案例、多个模型与固定后端配置的质量基准，以及失败率、重试成本和延迟统计。
6. 提示词文本质量。基础模式中完整主体描述被内联后仍可能出现重复冠词和标点；结构成功不表示表达已经自然、细节已经充分。

## 验证与发布限制

本地 `go test ./...`、`go test -race ./...`、`go vet ./...` 已通过，真实服务测试另行记录。GitHub Actions 的初始运行未启动作业，平台给出的原因是账户付款失败或 spending limit；这是远端验证缺口。不能把它说成 CI 通过，也不应为了显示绿色跳过检查。

在上述范围之外，调用方应得到明确错误；不更换模型、不删除模态、不修改模式、不截短文本、不返回假成功草稿。
